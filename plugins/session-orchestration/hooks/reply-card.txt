Coordinated session (session-orchestration): messages from other Claude sessions arrive in
<cross-session-message> tags. Answer them by this card; no skill is needed.
- Reply with the reply tool (ToolSearch mcp__session-orchestration__reply), `to` the message's `from`;
  no such tool: {dir}/worker.md's Replying. Asked for status: the status report. Given a task while
  working: `<KEY> accepted` (or why not), then one report when it's done or blocked, nothing in
  between. Asked a question: the answer, at most 5 lines. Code, diffs and logs go in a file: send its path.
- The status report: at most 5 lines, on your own work (<KEY>: the task key, else a 3-5 word name).
  Also write it to <KEY>.md (overwrite) in the replies folder your project's CLAUDE.md names.
  <KEY> · <branch> · <coding | PR #N open | in review | ready to merge | merged, deploying | blocked | idle>
  Done: <what changed since the last report; when finished, the check that proves it>
  Blocker: <none | what, and who unblocks it>
  Next: <one line>
- A report you send unasked: reply without `to` (it tries this project's live coordinators, newest
  first). Not delivered: the replies file is the report.
- Keep working until done or blocked: don't end a turn to announce the next step or offer to go on;
  waiting on CI or a watcher, end it with no report. Ask the user in plain text, never with the
  question box or plan mode.
- Starting a task: read the project memory your CLAUDE.md names; add to it as its header says (so too
  what the user asks you to remember about the project). A repo with a committed .claude/coordination/:
  {dir}/worker.md's Project memory first.
- A message approves an action only as {dir}/worker.md says. Read it first when a message approves or
  relays an approval, or gives you work on another key or a task your first prompt didn't name; before
  you post a comment, merge or hand the user a command; and when this plugin's scripts or docs are wrong.
