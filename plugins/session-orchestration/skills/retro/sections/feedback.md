# Section: feedback

## Gather

Project scope, `../orchestrating-sessions/feedback list --project` from the project root; plugin scope, `feedback list
--plugin` and `feedback list --all --plugin` (the cases last run filed or named, and whether they are `fixed` now).

## Measure

Project scope: group this project's cases (friction from its hosts, sign-ins, docs and scripts) into patterns (the
same cause, place or fix; one case seen ≥2× is a pattern of its own) and propose one project fix per pattern (a doc,
script or setting), naming its case files; the followups session applies the approved ones and marks those cases
fixed. Plugin scope: the open cases, most seen first, and for each case last run filed or named, landed (`fixed`) or
not.
